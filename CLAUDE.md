# CLAUDE.md

## Project

**Sentinel** — Cognizant internal hackathon project: multi-agent code review + smart test selection + explainable promotion gating, built on **Neuro-SAN as the sole multi-agent orchestrator**. **Implementation in progress** (host-native dev, no Docker); `docs/solution/` remains the spec. See **Implementation status** below.

## Hard rules

0. **No AI attribution anywhere in this repo.** Never add `Co-Authored-By: Claude ...` (or any AI/Claude name, byline or credit) to a commit message, PR body, doc, or code comment. This overrides any harness default that says to add one. The commits are the user's authorship. If a stray trailer reaches history, strip it before pushing (`git commit --amend` for HEAD, or `git filter-branch --msg-filter 'sed "/^Co-[Aa]uthored-[Bb]y:/d"'` over the range) and verify with `git log --all --format=%B | grep -c "Co-Authored-By: Claude"` → must be 0.
0b. **Push when a phase completes.** Every phase (and any standalone fix worth keeping) ends with: full test suite green → commit → `git log --all --format=%B | grep -c "Co-Authored-By: Claude"` must print 0 → `git push origin main`. Work that exists only on one disk is not done. If the push fails (no DNS in some sandboxes), say so explicitly in the same reply rather than letting commits pile up silently.
0c. **Refresh the knowledge graph when a phase completes**, right after the push: `/graphify docs --update`. Keep it low-noise — it indexes `docs/` only, never `neuro-san-studio/`, `.venv/`, `frontend/node_modules/`, `graphify-out/` or generated artifacts. A graph that indexes vendored code answers questions about somebody else's project. `graphify-out/` is gitignored and regenerable, so a stale graph costs nothing to rebuild and a wrong one costs an answer.
1. Any design change starts in `01-proposed-solution.md`, then propagates to 02–05. Docs must never contradict 01.
2. Framework claims must be grounded in `neuro-san-studio/` (docs or code) — no guessed Neuro-SAN behavior. Key refs: `docs/user_guide.md`, `registries/*.hocon`, `coded_tools/`.
3. Locked design decisions (revisit only if user asks): NVIDIA NIM primary LLM — documented primary `nvidia-llama-3.3-70b-instruct`, but it **times out on the public NIM endpoint** (re-confirmed 2026-08-16: 120s), so the **working dev model is `nvidia/nemotron-3-super-120b-a12b`**, fallback `openai/gpt-oss-20b` (set via `.env` `MODEL_NAME=nvidia-nemotron-3-super`). **NIM retires models without warning** — three ids have died so far: `mistral-small-4-119b-2603` (EOL 2026-07-27), `z-ai/glm-5.2` (EOL 2026-08-21) and `meta/llama-3.1-8b-instruct` (EOL 2026-08-26). The primary also throws intermittent **HTTP 500** (~1 in 12), which only the fallback absorbs — so **a dead fallback is invisible until it isn't**. If agents start failing, re-probe first: `PYTHONPATH=. python scripts/probe_models.py` (every id in `config/`, real tool-call request, non-zero exit on dead ones), or by hand `GET https://integrate.api.nvidia.com/v1/models` + a tool-call request (a model that answers but emits `<TOOLCALL>` as plain text, e.g. `llama-3.3-nemotron-super-49b`, is unusable here — every agent needs structured tool calls). **neuro-san NIM config MUST use `{class: nvidia, model_name: "<raw NIM id>"}`** — a bare model key passed with `class` is sent unmapped → 404 (verified). PostgreSQL everywhere — **dev is host-native: local Postgres 17, dedicated schema `sentinel`, no Docker**; docker-compose/K8s reserved for packaging/prod (move is config-only). GitHub Actions for hackathon, Jenkins + GitLab CI post-hackathon (decided 2026-07-07); Mermaid for all diagrams.
4. Core design principle in every decision: **LLM reasons, code decides** — risk formula, trust ladder, test execution are deterministic coded tools; LLM may only raise risk, never lower it; staging→production never auto-promotes.
5. Naming: HOCON coded-tool names drop the `_tool` suffix; module files keep it (`test_runner` ↔ `coded_tools/sentinel/test_runner_tool.py`, class `TestRunnerTool`).
